# 실험 프로토콜 v0.1

작성일: 2026-10-29. 상태: **전향적 개발 벤치마크 초판, 사전등록된 확증 연구 아님**.

## 질문과 조건

질문: 행동 사전과 LLM의 추론으로 만든 중간 레퍼런스가 직접 I2V 대비 최종 영상의 명시 행동 요구 충족률을 높이는가? 레퍼런스 검증·수정은 잘못된 중간 제약의 피해를 줄이는가?

각 사례에서 이미지 바이트와 요청 원문을 고정한다. A는 직접 I2V, B는 LLM 최초 레퍼런스를 사용하는 R2V, C는 **B의 동일 최초 레퍼런스**를 검사하고 최대 한 번 수정한 R2V다. 같은 반복 안에서 B/C의 초기 계획·초기 레퍼런스 해시를 공유해 검증 효과와 서로 다른 최초 샘플의 효과를 구분한다. C가 통과시키면 B/C의 레퍼런스가 같을 수 있다. 이것을 강제로 다르게 만들지 않는다.

LLM이 사전을 참조하지 않는 조건, 검증 비용을 맞춘 조건, 초기 자세 정답을 제공하는 oracle 조건은 v0.1에 포함하지 않는다. 추가 시 별도 ablation으로 명명한다.

## 사례와 누출

| 분할 | 문항 | 용도 |
|---|---:|---|
| development | 8 | 추론/검증 구현, 실패를 보고 수정 가능 |
| calibration | 4 | 평가자 설명과 채점 연습; 점수 향상의 근거로 사용하지 않음 |
| test | 12 | 고정된 파이프라인의 평가; 결과를 보고 같은 버전의 코드/프롬프트를 수정하지 않음 |

평가 12개는 사전 관계 3개 × 초기 자세 4개의 각 셀에 한 사례다. 최소 커버리지 검사이며 충분한 통계적 표본이 아니다. 행동군 반복을 독립 사례처럼 과대해석하지 않는다. 알려진 행동과 자세 유형은 분할 사이에서 공유되며, 사전 밖 평가 행동군 `bow`, `cross_arms`만 개발/채점 연습에서 제외된다. 조합 조건은 새로운 순서/횟수의 일반화이지 모든 구성 요소의 홀드아웃이 아니다.

사전 버전은 `benchmark/seed_dictionary.json`으로 고정한다. 새 seed 동작을 추가하면 일부 문항의 novelty 정의가 달라지므로 새 벤치마크 버전이 필요하다. 원본 동작 코퍼스 전체를 검색 가능하게 열어 두고 seed 밖이라고 주장하면 안 된다. LLM 사전학습 데이터에 대한 미관측을 주장하지 않는다.

평가용 관절 좌표/채점 계약은 generator packet에서 제외한다. 검증기는 요청과 입력 이미지로 독립적으로 계약을 추출해야 하며 저장된 evaluator 정답을 읽지 않는다. 공개 저장소의 테스트는 비밀 테스트가 아니다. 연구자가 테스트 문항에 맞춰 튜닝하면 해당 버전은 개발 데이터로 전환하고 새 테스트를 작성한다.

## 예산과 재시도

권장 첫 기능 시험: development, 조건당 1회 = 24개 최종 슬롯. 이후 고정 평가: test, 조건당 3회 = 108개 최종 슬롯. 코드의 기본값은 3회이므로 `--repeats 1`을 명시하면 소규모 개발 실행이 된다.

각 반복마다 최초 LLM 계획/레퍼런스 1개를 생성해 B/C에 공유한다. C에만 검증 1회와 필요한 경우 수정 1회, 수정 결과 재검사 1회를 허용한다. 재검사 실패 시 C를 `blocked`로 기록한다. B는 내용 검증 없이 제출하되 파일 손상/규격 오류는 공통 전송 검사에서 처리한다. 최종 영상의 미관이 나쁘다는 이유로 재생성하거나 최고 결과만 선택하지 않는다. 전송 오류의 재시도는 최대 1회이며 같은 attempt의 로그에 남긴다.

최종 모델/배포 ID, planner와 verifier ID, temperature/seed, 이미지/레퍼런스 역할, 출력 길이/비율/해상도, 오디오 설정과 수치 비용 상한을 실제 실행 전에 기록한다. 비용은 현재 제공자 가격과 예상 토큰/영상 길이에 따라 계산해야 하므로 초판에는 금액을 꾸며 넣지 않았다. 검증을 추가한 C의 전체 비용과 지연은 B보다 클 수 있다. 동일 최종 생성 횟수가 동일 전체 계산비용은 아니다.

I2V의 first-frame 모드와 R2V의 reference-image 모드가 다르면 첫 프레임 강제 일치는 동등 조건이 아니다. 지원 여부를 실제 엔드포인트 문서/호출로 확인하고 시작 이미지 연속성을 별도 결과로 평가한다. 동일 숫자 seed가 서로 다른 conditioning에서 동일 확률표본을 뜻하지 않는다.

## 평가와 분석

주 결과: 사례마다 배정된 반복 중 모든 명시 요구를 충족한 비율을 계산하고 사례 간 평균을 낸다. 최종 실패/중단은 0, 합의된 불확실도 성공이 아니므로 0이며 각각의 수를 따로 공개한다. 아직 실행하지 않거나 평가하지 않은 슬롯은 완료된 실패가 아니므로 전체 주 점수는 `null`이다. 두 평가자가 요구별로 다르면 제3자의 판정 전에는 `disputed`로 유지한다.

부 결과: 신체/외형 보존, 초기 자세 연속성, 시간적 흔들림, 자연스러움, 레퍼런스 자체의 요구 충족, 비용, 지연, 중단율. 하나의 임의 가중 점수로 합치지 않는다. `summarize`는 v0.1에서 주 결과와 대응 사례 차이만 계산하며 부 결과 분석은 기록 양식/후속 분석 대상이다. 신뢰구간과 유의성 검정은 아직 구현하지 않았다. 추가할 때는 행동군/사례 단위 의존성을 반영해야 한다.

평가자는 입력 이미지·원문 요청·익명화된 영상만 본다. 계획 설명, 조건명, gate 결과는 숨긴다. 시각적 차이로 조건을 추측할 가능성은 남는다. 두 사람의 독립 판정을 사용하며 LLM 자기평가를 사람의 자연스러움 평가로 대체하지 않는다. 현재 실제 독립 평가는 진행하지 않았다.

## 실패 위치

초기 자세 해석 → 행동 계약 → LLM 키프레임 계획 → 리타기팅 → 레퍼런스 검사 → 최종 영상 생성 → 전송/파일 오류를 분리한다. 어떤 단계의 출력이 없으면 원인을 확정하지 않고 근거가 있는 마지막 단계까지만 기록한다. 최종 영상만 보고 LLM/리그/영상 모델 중 하나를 임의로 탓하지 않는다.

## 변경 규칙

문항, 입력 이미지, 사전, 채점 계약은 해시로 묶는다. 테스트 출력 확인 후 수정된 문항/파이프라인으로 같은 버전의 평가를 계속하지 않는다. 새 버전을 만들고 변경 이유와 이전 실패를 남긴다.
