# dev-002 중단 기록: 자세 호출에 리그 설명이 빠진 버그 (2026-10-29)

**무슨 일이 있었나:** `--pose-fit` 변형으로 development 8건을 실행하던 중 4건이 계획됐을 때 중단했습니다. D01–D03은 이미 레퍼런스 렌더와 등록까지 마친 상태였습니다.

**증상:** 실루엣 맞춤 점수가 0.015–0.035에서 시작해 0.03–0.06에서 끝났습니다. dev-001 프로토타입은 0.4–0.6에서 시작했습니다. LLM 자세는 y를 높이로 쓴 좌표였습니다(예: 골반 (0, 1, 0)). 이대로 그리면 마네킹이 바닥에 누운 모습이 됩니다. 계획 호출도 이 자세를 고정값으로 받아 그대로 이어 썼습니다.

**원인 (코드 버그):** 리그 설명을 `RIG` 변수로 빼는 리팩터링에서 문자열 치환이 잘못된 위치에 적용됐습니다. 그 결과 `RIG`가 리터럴 `"{RIG}"`가 되어, 자세 호출 프롬프트에 좌표계·관절 설명이 아예 들어가지 않았습니다. 계획 호출 프롬프트에는 원문이 남아 있어서 dev-001은 영향을 받지 않았습니다(해시 동일 확인).

**조치:**
- `RIG`를 복구했습니다. 계획 프롬프트 해시는 dev-001과 같습니다.
- 정답 없이 쓸 수 있는 좌표 관례 검사 `pose_sanity`를 추가했습니다. 초기 자세는 머리가 골반보다 위에 있고 한쪽 발이 바닥 근처여야 하며, 모든 키프레임은 바닥 아래로 내려가면 안 됩니다. dev-001 8건은 모두 통과하고 dev-002 4건은 모두 거부됩니다.
- 맞춤 겹침 하한 `FIT_MIN=0.5`를 두었습니다. 이보다 낮으면 `initial_pose` 실패로 기록하고 계획 호출로 넘어가지 않습니다.
- 새 run(dev-003)에서 다시 실행합니다. dev-002 ledger는 수정하지 않고 그대로 남깁니다.

**교훈:** 리팩터링 뒤 해시 비교는 계획 프롬프트에만 했고, 새로 생긴 프롬프트의 내용은 확인하지 않았습니다. 지금은 시험(`test_pose_prompt_carries_the_rig`)이 이를 막습니다.
