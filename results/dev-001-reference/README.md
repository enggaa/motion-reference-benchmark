# dev-001 레퍼런스 렌더 (development 8건, 2026-10-29)

**무엇인가:** `results/dev-001-planner`의 실제 계획 8건을 레퍼런스 영상(MP4)으로 렌더링한 결과입니다. MP4는 `.gitignore` 대상이라 커밋하지 않았고, 영상 해시는 각 `*_telemetry.json`에 남겼습니다. 아직 `reference_initial`로 등록하지 않았습니다. 시댄스 R2V 호출과 사람 평가도 없습니다.

## 렌더러가 하는 일 (`motionbench/animate.py`, `tools/render_reference_blender.py`)

- **뼈 길이**: 계획 0초 키프레임 기준으로 고정합니다. 8건 모두 프레임별 오차가 1e-15 m 수준입니다.
- **몸통과 팔**: 뼈 방향을 보간합니다(단조 Hermite). 처음에는 관절 위치를 직선 보간했는데, D01에서 팔을 드는 중간에 팔꿈치가 옆으로 꺾이는 자세가 나와서 방향 보간으로 바꿨습니다.
- **다리**: 발목 위치를 향한 2관절 IK를 씁니다. 그래서 디딘 발이 미끄러지지 않습니다.
- **닿을 수 없는 목표**: 뼈를 늘리지 않고 닿는 데까지만 갑니다. 그 대신 부족한 거리와 키프레임 오차를 기록합니다.
- **그리기**: 입력 이미지와 같은 절차적 마네킹, 같은 카메라, 같은 조명을 씁니다. 576×768, 24fps입니다. 계획이 앉기면 의자를 넣습니다.
- **알려진 차이**: 사례마다 몸 색이 조금 다른 변형(render_variant)은 생성 측이 알 수 없어서 기본색으로 그립니다.

## 눈으로 확인한 것 (`first_frame_vs_input.png`, `contact_*.png`)

- **첫 프레임과 입력 이미지 비교**:
  - D02, D06(앉기), D07은 거의 같습니다.
  - D01, D05(서기)는 계획이 골반을 낮게 잡아서 키가 약간 작고 팔이 몸에 붙어 있습니다.
  - **D08은 입력과 반대 방향으로 기울어진 채 시작합니다.** 계획의 초기 자세 오류가 실제 레퍼런스 출력에서도 그대로 보입니다.
- **동작 순서**: D02(앉아서 왼손), D05(오른손→왼손), D06(앉아서 왼손→오른손), D04(일어서기), D07(머리 위 유지 후 내림), D08(몸 세우기→허리에 손)은 요청한 순서대로 움직입니다.
- **카메라에서 잘 안 보이는 동작**: D01과 D03은 "몸 앞에서" 흔드는 요청이라, 이 카메라에서는 흔드는 손이 자기 팔과 몸에 일부 가립니다. 레퍼런스가 최종 모델에 동작을 전달할 수 있는지는 별도 문제로 남습니다.

## 해석의 한계

이 결과는 렌더러가 계획을 그대로 그렸다는 기계적 확인일 뿐입니다. 요구사항 충족 여부는 사람 평가로 판정해야 하고, 그 평가는 하지 않았습니다. 사례 8개를 1회씩만 렌더링했습니다.
