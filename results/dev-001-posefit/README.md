# 초기 자세 실루엣 맞춤 (development 8건, 2026-10-29)

**무엇인가:** dev-001에서 LLM이 추정한 초기 자세를 출발점으로 `motionbench/posefit.py`의 렌더-비교 맞춤을 돌렸습니다. 이 맞춤은 LLM을 호출하지 않습니다. 맞춤 후 자세를 평가 정답과 비교한 것은 개발 측 분석일 뿐이고, 정답이 생성 쪽으로 들어가지 않습니다.

## 방법

1. **후보 그리기**: LLM 자세에 몇 가지 변화를 준 후보들을 입력 이미지와 같은 마네킹·카메라로 그립니다. 바꾸는 값은 몸통 좌우·앞뒤 기울기, 크기, 위치, 팔 좌우·앞뒤 방향, 팔꿈치 굽힘입니다.
2. **점수**: 입력 이미지와의 겹침입니다. 실루엣 IoU와 피부색(얼굴·손) IoU의 평균을 씁니다. 화소의 빨강−파랑 값으로 피부색(+5 이상), 파란 몸(−14 이하), 회색 배경과 의자(그 사이)를 나눕니다.
3. **탐색**: 단계별로 진행합니다. 몸 전체(기울기·크기·위치) → 팔 방향 → 전체 순서이고, 매 단계 한 칸과 두 칸 이동을 함께 시도합니다.
4. **벌점**: 변화량에 벌점을 줍니다. 한 시점에서 깊이가 안 보이는 앞뒤 방향 변화는 2배입니다.

## 먼저 시도했다가 버린 방법

LLM에게 입력, 현재 추정의 렌더, 겹침 차이를 나란히 보여 주고 관절을 고치게 했습니다(D08, 2회). 두 번 모두 겹침이 줄었고(0.58 → 0.50 → 0.54), 기울기를 더 틀린 쪽으로 밀었습니다. 그래서 수정은 수치 탐색으로 하고, LLM은 첫 추정, 자세 분류, 접촉 정보만 맡게 했습니다. 2회 시도에 그친 관찰이라 LLM 수정이 원리적으로 불가능하다는 뜻은 아닙니다.

## 한계

- **카메라 가정**: 입력이 같은 마네킹·카메라로 렌더링됐다는 가정에 기댑니다. 이 합성 벤치마크에서만 성립합니다.
- **깊이 모호성**: 벌점으로 줄였을 뿐 사라지지 않았습니다. D08 맞춤 결과는 좌우 12°에 앞뒤 기울기도 일부 섞여 있습니다.
- **표본**: 이 표는 dev-001 계획의 초기 자세에 사후로 적용한 결과입니다. 실제 파이프라인(dev-002)은 별도의 자세 호출부터 시작하므로 값이 다를 수 있습니다. 사례는 8개, 각 1회입니다.
